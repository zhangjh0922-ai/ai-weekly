**本期发布于 11 月 2 日，重点关注上周，也补齐 10 月 19 日以来的更新。** 上一期停在 10 月 19 日，因此这次覆盖两周，文中均标明具体日期。

本期继续跟进文件编辑、电脑操作和持续任务工具。变化分别发生在不同环节：Terra 与 Kimi 发布新版本，Gemini 更新文件编辑体验，Claude Duet 开启候补预览，Notion 调整 Agent 功能与额度。对使用者来说，值得关注的是具体产品相较之前改了什么、开放给谁，以及哪些步骤仍需要自己接手。

以下基于官方公告、模型卡和更新日志核查，**尚未进行统一实测**。用途与评测建议属于编辑判断；厂商演示和跑分不直接当作我们的使用结论。

## 电脑操作与编程：模型迭代和接口正式开放

### GPT‑6.1 Terra：延续电脑任务定位，降低 API 价格

**10 月 26 日**，OpenAI 发布 GPT‑6.1 Terra，延续 Terra 系列对视觉理解、电脑操作和写作的定位。官方称新版相较 GPT‑5.6 Terra 改进了这些任务的表现，同时降低标准 API 价格。它已进入 API，并在 ChatGPT Work、Codex 中提供，**普通 Chat 标签页没有这个选项**。[发布公告](https://openai.com/index/introducing-gpt-6-1-terra/)、[开放说明](https://help.openai.com/en/articles/9624314-model-release-notes)

标准 API 每百万输入、缓存输入、输出 token 分别为 **1、0.05、5 美元**。对需要反复读取页面、执行很多小步骤的任务，成本是一个实际变化。是否更省时间，还需要看它能否一次做对，以及出错后能否自己恢复。[定价与定位](https://openai.com/index/introducing-gpt-6-1-terra/)

### Gemini Computer Use：开发接口正式可用

**10 月 30 日**，Gemini API 的 Computer Use 进入正式可用阶段，覆盖 Interactions 与 GenerateContent 接口。模型根据截图提出点击、输入等动作，开发者的程序负责执行，再把新截图交回模型。这不是“所有 Gemini 用户都能直接遥控电脑”的公告；接入方仍需提供运行环境和权限控制。[API 更新日志](https://ai.google.dev/gemini-api/docs/changelog)、[工具说明](https://ai.google.dev/gemini-api/docs/computer-use)

### Kimi K3.1 Pro：模型版本更新，3D Make 上线

**10 月 23 日**，K3.1 Pro 系列进入 Kimi Code；**10 月 24 日**的完整公告确认网页、App、Kimi Work 与 API 入口，并介绍已经在网页与 App 上线的 3D Make，可预览、修改和导出生成的 3D 内容。[Kimi Code 日志](https://www.kimi.com/code/docs/kimi-code/whats-new.html)、[模型公告](https://www.kimi.com/news/kimi-k3-1-pro)

Kimi Code 的 Pro 模型需要 Plus／Moderato 及以上会员，最高 1M 上下文和 Highspeed 需要更高档位。Highspeed 按同一模型的高速服务说明，不另算一种底层能力；完整权重计划在 11 月 4 日前开放，**截至本期仍不能写成已经开放权重**。[功能与套餐说明](https://www.kimi.com/code/docs/kimi-code/whats-new.html)

## 文件与长期任务：更接近日常使用的更新

### Gemini：文件预览与编辑体验更新

**10 月 29 日**，Google 公布 Gemini 的文件预览与编辑体验更新：在生成文件的预览中直接修改内容、选中片段让 AI 重写，或继续用对话调整。此次公布的 PDF 预览与编辑支持网页和移动端；文档、表格、演示稿、Markdown、TXT 和代码的直接编辑在网页端提供，面向 Gemini 已开放地区的所有用户与语言。[官方说明](https://blog.google/innovation-and-ai/products/gemini-app/edit-files-directly/)

这很适合检验一个具体问题：把课堂笔记整理成复习资料后，能否只改错的公式、某一段解释或一个表格，而不破坏其余排版。文件能生成出来只是第一步，后续修改是否方便同样重要。

### Claude Duet：新应用开启候补预览

**10 月 21 日**公布的 Claude Duet 是主动处理事务的新应用，可以根据已连接的邮箱、日历等服务准备简报，也能在自己的云端电脑和浏览器里继续工作。预览从美国的 Pro、Max、Ultra 用户开始，需通过候补名单获得邀请；Team、Enterprise 尚未开放。它使用现有套餐额度，后台工作也会消耗用量。[产品公告](https://claude.com/resources/articles/claude-duet)、[使用条件](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet)

目前不能实时观看或接管它的云端浏览器，Microsoft 365 也未接入。发送消息、付款、签署或删除等动作设计为先请求批准。评估这类产品时，值得同时看它做了什么、依据什么，以及遇到限制时能不能说清楚。[当前限制](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet)

### Notion Agent：运行能力与额度体系调整

**10 月 19 日**，Notion 公布重建后的 Agent，支持借助自己的电脑、浏览器执行长任务，并通过 MCP 同步记忆。新客户当天启用，老客户按公告于 **11 月 2 日**迁移新的额度体系；我们没有登录账户验证迁移完成。[功能日志](https://www.notion.com/releases)、[官方说明](https://www.notion.com/blog/notion-ai-more-for-less)

Business／Enterprise 每席每月包含 1,500 Standard credits 和 500 Select credits，分别用于 Auto 自动选模型与自主选模型／Custom Agents 等场景。AI Command Center、通过 MCP 提供 Skills 仍写着即将推出。使用前应区分哪些能力已经开放、哪些仍在计划中。[计费与开放说明](https://www.notion.com/blog/notion-ai-more-for-less)

## 网页与创作工具：项目、图片素材和交互原型更新

**GitHub 在 10 月 28 日集中更新 Copilot。** App Projects 进入公开预览，可围绕同一目标放入仓库、设计稿和笔记，组织后台任务；Copilot 对话内也增加生图与图片编辑入口，向付费套餐开放预览，可以把生成素材直接存进项目。图像工具另计用量。[Projects](https://github.blog/changelog/2026-10-28-github-copilot-app-universe-releases/)、[图片工具](https://github.blog/changelog/2026-10-28-generate-and-edit-images-directly-in-copilot/)

同日开源的 **Replica** 可以沿用团队已有组件和设计规则制作交互原型。整合此前 Auto 与 HydraFusion 的 **Fusion** 模型路由正式可用，可以自动选择模型或交叉检查结果；本地与云端模型路由则仍是另一个实验预览。对于做网站的人，值得测试的是页面能否保持风格一致、素材是否合适、交互是否完整，而不只是生成速度。[Replica](https://github.blog/changelog/2026-10-28-introducing-replica-an-open-source-ai-prototyping-tool/)、[Fusion](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion/)、[本地模型预览](https://github.blog/changelog/2026-10-28-github-copilot-fusion-now-supports-selection-of-local-models/)

**Runway App Studio 于 10 月 26 日上线**，可以用自然语言把图像、视频、音频工作流做成有界面的应用并分享。付费用户可创建，构建、运行和托管消耗 credits；公开链接的使用者仍需登录 Runway，并使用自己的生成额度。它适合把反复做的创作步骤做成工具，不能当作任意访客都能免费使用的普通网站托管。[发布公告](https://runway.com/news/company-news/introducing-runway-app-studio)

开发者方面，**Cursor Agent SDK 于 10 月 20 日正式可用**，支持定义工具、技能与触发方式，在本地评测后部署；**10 月 28 日**，GitHub Copilot SDK 更名为 Microsoft Copilot SDK，配套运行框架也向开发者开放。这些更新涉及开发工具与部署方式。[Cursor](https://cursor.com/changelog/agent-sdk)、[Microsoft](https://blogs.microsoft.com/blog/2026/10/28/introducing-the-microsoft-copilot-harness-unlocking-the-potential-of-truly-multi-model-agentic-work/)

## 值得关注，但还不能当作人人可用

- **Gemini 4 Carbon，10 月 28 日**：重点是长时间软件工程与网络防御任务。首批面向部分防御人员，并经 Fairwind 计划扩展可信合作方；普通开发者、企业和消费者的开放仍是后续安排。[Google 公告](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/)
- **Genie 4，10 月 27 日**：Google 在这一代实时交互世界模型中加入原生音频生成，可同时生成场景、环境声和角色对话，并在运行中用语言改变场景。目前是可信测试者研究预览，Project Genie 的 Ultra 用户和 API 合作方属于后续开放计划。生成的场景也不能直接当作可靠的物理实验。[DeepMind 公告](https://deepmind.google/blog/genie-4-a-new-generation-of-world-simulation/)
- **GPT‑6 Rosalind Research，10 月 30 日**：面向生命科学研究，仅向部分获批 Research 客户开放 Work、Codex 和 API。Discovery 资格不能自动换取 Research 资格，普通聊天中也没有入口。[模型发布记录](https://help.openai.com/en/articles/9624314-model-release-notes)

## 几项容易影响使用的小变化

- **ChatGPT API 赠额，10 月 28 日**：符合条件的 Pro、Business 订阅可领取，额度取决于套餐与席位，最高每月 500 美元；需要满足订阅时长并关联自己拥有的 API 组织。它不增加 ChatGPT 或登录版 Codex 的额度，也不支持以 API key 使用 Codex。这不是“所有付费用户都送 500 美元”。[额度与条件](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)
- **ChatGPT 表达风格，10 月 29 日**：减少冗长与过度奉承，适用于 Free、Go、未登录用户，以及 Plus／Pro 触及限额后的备用模型；Plus／Pro 的主 GPT‑6 模型未因此改变。[模型更新记录](https://help.openai.com/en/articles/9624314-model-release-notes)
- **ChatGPT iCloud 连接，10 月 27 日**：邮件与日历插件面向所有套餐，可以查邮件、概括收件箱和处理日程，仍需用户连接自己的账户。[产品日志](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)
- **Claude API 迁移，10 月 21 日**：新的 API 版本伴随主要 SDK 大版本更新和不兼容变化。维护应用时需要先看迁移说明，不能只升级依赖版本。[迁移指南](https://platform.claude.com/docs/en/api/migration-2026-10-21)
- **MiMo Code 迁移，10 月 26 日**：v0.1.16 退役旧 Compose 主智能体及相关工作流、技能，复杂任务改用 build 模式的 `/compose-next`；已有脚本或习惯需要调整。[版本说明](https://github.com/XiaomiMiMo/MiMo-Code/releases/tag/v0.1.16)

## 下一次实测，可以从这三件事开始

这些是后续评测题目，还不是本期实测结果。

1. **做一份能继续修改的资料**：给各产品相同的笔记和参考材料，生成两页学习资料，再要求只修改其中一处。检查事实、引用、公式和排版有没有一起保住。
2. **完成一个网页任务**：在专门的测试网站里查找信息、填写表单、保存结果，再故意加入一个失败步骤。记录完成情况、人工接手次数和恢复方式。
3. **做同一份网页设计**：使用相同需求和素材，展示最终页面与操作录像；把功能完成度与个人审美感受分开记录，不先给所有风格排一个总分。

这样既能看到底层模型的理解和推理，也能看见产品工具、执行环境和交互设计带来的差别。

**核查范围**：本期交叉检查了主要国内外模型厂商，以及文档、编程、检索与多媒体产品的官方来源，优先收录影响实际使用的变化。App 内灰度、地区和账号开关未逐一实测；尚无正式开放证据的预告不按已发布处理。更早的补录可见[上一期特刊](/issues/2026-autumn-catchup)。
